# patch44 | 2026-11-16 | Dependencies in ~/EmuSPLASH/dependencies
* At startup EmuSPLASH checks its dependencies in the background, the same on every
  distribution (a short notification while something is downloaded, the result in the log):
  - yt-dlp: the standalone one of GitHub (no Python needed) in dependencies/bin/yt-dlp. It's
    downloaded when missing and updates itself once a week (yt-dlp -U). The trailers use it
    first, then EMUSPLASH_YTDLP or the yt-dlp of the system if the download failed. The
    earlier copy in ~/EmuSPLASH/yt-dlp (it needed Python) is removed.
  - Deno: yt-dlp needs a JavaScript runtime for YouTube. Without deno in the system it's
    downloaded to dependencies/bin/deno, yt-dlp finds it there.
  - Python 3: the one of the system is used. Without it a standalone Python 3
    (python-build-standalone, 3.12) is downloaded to dependencies/python and the add-ons use it.

# patch42 | 2026-11-15 | EmuSPLASH 1.0.0
* The application is EmuSPLASH, version 1.0.0: the program is emusplash (/usr/bin/emusplash,
  /usr/share/emusplash), with a new splash screen, icon and desktop entry
  (org.emusplash.frontend). It's based on ES-DE (MIT), see README.md and CREDITS.md.
* RetroArch's settings file is emusplash.cfg (es-de.cfg is renamed), the copies of the
  emulators' files are *.emusplash-backup (an earlier *.es-de-backup is renamed).
* The launch commands Suspend EmuSPLASH and Keep EmuSPLASH running replace the ones named after
  ES-DE, a game or system that had the old name keeps its choice.
* No application updater (it checked the ES-DE releases). The theme downloader stays.
* The default theme is Iconic (iconic-es-de), installed from themes/iconic-es-de without its
  .git folder and the Windows scripts. When a configured theme is missing, Iconic is used,
  then Linear.
* Other settings has no RUN IN BACKGROUND (WHILE GAME IS LAUNCHED) any more, and the setting
  is ignored: EmuSPLASH waits for the game, which the hotkeys need. With it on, close game did
  nothing (RPCS3 on the HTPC didn't close). A launch command with %RUNINBACKGROUND% still runs
  in the background.

# patch38 | 2026-11-12 | Several ROM directories, close game for every game
* Other settings > ROMS DIRECTORY: the ROM directory and up to two more (ADD ANOTHER ROMS
  DIRECTORY, a directory can be changed or removed). The folders of the systems are made in a
  new directory as the first time, the games of all directories are in the same systems
  (snes of every directory is one SNES), their media in the same folders. Games of the other
  directories are kept in the gamelists with their full paths, also by the orphaned data
  cleanup.
* Close game reads the pads from /dev/input too, not only with SDL (SDL may not get the
  buttons while the emulator has the focus), a combination counts after 50 ms instead of
  150 ms. Pressing it again ends the game at once, a third time kills it. Also the processes
  started by the game are ended (an AppImage or a launcher may not keep the output pipe).
  An emulator that got the close hotkey gets 2 seconds to close itself instead of 4.
* CLOSE GAME can also be START + a button. RetroArch takes its enable button from save state,
  load state or fast forward first, close game with another button is done by EmuSPLASH.
* The text of HOTKEYS is one text that scrolls by itself while it's selected.
* RPCS3: PREFERRED SPU THREADS, ACCURATE RSX RESERVATION ACCESS, STRICT RENDERING MODE,
  RELAXED ZCULL SYNC and ANTI-ALIASING (MSAA).

# patch37 | 2026-11-11 | Emulator settings checked, Cemu and RetroArch, more hotkeys
* Contains patch36, which didn't apply to the sources of patch35 (PlatformUtil.h).
* The numbers of the Switch emulators are the ones of their sources: Eden has its own
  resolutions (1X is 3, with 1.25X), filters (Lanczos, FSR is 6, Area) and two GPU accuracies
  (Low, High), citron four (Low, Normal, High, Extreme) and only the first four filters (the
  place of its FSR isn't known), suyu the 32:9 aspect ratio. Eden has RESOLUTION and SCALING
  FILTER again.
* RPCS3: SHADER MODE. PPSSPP: VSYNC (VerticalSync). Vita3K: GPU HIGH ACCURACY. The VSync and
  FSR values of RPCS3 are the ones it writes (Disabled, Adaptive, Full, FidelityFX Super
  Resolution).
* ADVANCED GAME OPTIONS for more games: Cemu (gameProfiles/<title ID>.ini with the graphics
  API, CPU mode and accurate shader MUL; the title ID from meta/meta.xml of a game folder or
  from the title list of Cemu, so .wux and .wua work), PCSX2 with every format (.chd too) from
  the game list of PCSX2 (cache/gamelist.cache), PPSSPP also with .cso files, Switch NSP files
  without the title ID in the name (from the ticket in the NSP). AUTO shows the value of the
  emulator. A new game file of PPSSPP also gets the controls.
* RetroArch in EMULATOR SETTINGS and ADVANCED GAME OPTIONS: graphics driver, VSync, bilinear
  filtering, integer scaling, aspect ratio, shaders, threaded video, run-ahead and rewind.
  retroarch.cfg isn't changed: the settings are kept in ~/EmuSPLASH/retroarch (emusplash.cfg and
  games/<system>/<game>.cfg) and given to RetroArch with --appendconfig. With Vulkan the
  AppImage gets the libwayland-client of the system (LD_PRELOAD).
* Hotkeys into RetroArch (~/EmuSPLASH/retroarch/hotkeys.cfg): the buttons are counted as its
  joypad driver counts them, Select is the enable button, one press closes. RPCS3: the save
  state hotkey presses its keyboard shortcut (Ctrl+S or its own) with XTest (libxtst6).
  PCSX2 keeps the keyboard keys of a hotkey, the pad binding is added next to them. The
  emulator gets 4 seconds to close itself only if the hotkeys were written into it.
* Close game also works when SDL has no pad, the pad is then read from /dev/input.
* Launch commands with escaped spaces (New\ Folder), flatpak run and %ENABLESHORTCUTS% are
  recognized. Files of games get no *.emusplash-backup, and a file that doesn't end with a newline
  stays so.

# patch36 | 2026-11-11 | Emulator settings, game options and hotkeys
* New module (es-app/src/emulators) that knows the settings files of Eden, citron, suyu, yuzu,
  RPCS3, PCSX2, PPSSPP, Cemu and Vita3K, finds the emulator of a game from its launch command
  (also of a shortcut) and changes only the lines of the settings it is asked to. The first
  time a file is changed a copy is kept next to it (*.emusplash-backup).
* Other settings > EMULATOR SETTINGS (first row): the emulators whose settings file exists,
  each with its important settings (graphics API, resolution, aspect ratio, anti-aliasing,
  anisotropic filtering, FSR, VSync, CPU and GPU accuracy, multicore, asynchronous shaders,
  disk shader cache, force max clock, ASTC, and the CPU settings of RPCS3 and PCSX2). The
  menu shows what is in the file of the emulator and writes the changes into it. A setting
  that isn't in the file is "EMULATOR DEFAULT" and stays so unless changed.
* Game options > ADVANCED GAME OPTIONS: the same settings for one game, AUTO keeps the one of
  the emulator. They go into the files of the emulator for one game: custom/<title ID>.ini of
  the Switch emulators (the title ID of the file name), custom_configs/config_<serial>.yml of
  RPCS3 (from the shortcut or PARAM.SFO), gamesettings/<serial>_<CRC>.ini of PCSX2 (read from
  .iso files) and <ID>_ppsspp.ini of PPSSPP (from UMD_DATA.BIN of .iso files or the file
  name). Cemu and Vita3K have only the emulator settings.
* Input device settings > HOTKEYS: close game, save state, load state and fast forward, each
  Select with a button, two other combinations or off (default Select + B/Circle, R1, L1, R2).
  Close game is watched by EmuSPLASH while the game runs and ends the emulator, with every
  emulator. The hotkeys are also written into PCSX2, PPSSPP and the Switch emulators before a
  game starts with them (row "Write the hotkeys into the emulators"); these get 4 seconds to
  close themselves before EmuSPLASH ends them.

# patch35 | 2026-11-10 | Added emulators aren't lost at the next start
* An emulator added to a system went into the custom systems file with only the extensions
  that file had (e.g. PS3 without .desktop). That entry then had no games and wasn't used, the

* The row in Alternative emulators is "ADD APPIMAGE, .SH SCRIPT OR BIN FILE...".
